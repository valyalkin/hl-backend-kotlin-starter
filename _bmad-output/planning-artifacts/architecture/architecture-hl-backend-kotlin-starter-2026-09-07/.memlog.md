- (decision) Package layout = LAYER-FIRST (user chose over my feature-first lean). Root com.hl.starter; domain/{shared,<resource>}, application/<resource>, adapter/in/web/{shared,<resource>}, adapter/out/{persistence,cache}/<resource>, plus StarterApplication.kt at root. Binds: FR-4, FR-6, SM-2, SM-4. Prevents: two resources landing code in different trees. Upside kept: ArchUnit's layeredArchitecture DSL maps 1:1 onto these package roots, so FR-5 rules are expressible directly rather than as slice rules. Cost accepted: deleting the Example Slice (SM-4) and adding a resource (SM-2) are multi-directory operations, so the README checklist must enumerate every path.
- (decision) Application layer gets a NARROW Spring allowance: @Service/@Component (org.springframework.stereotype) and @Transactional (org.springframework.transaction.annotation) permitted; everything else Spring banned. Boundary Test explicitly forbids in application: org.springframework.web.., org.springframework.data.., org.springframework.http.., jakarta.persistence.., jakarta.servlet.., org.hibernate.. . Domain stays 100% framework-free (no Spring, no Jakarta, no HTTP). OVERTURNS PRD FR-5 assumption ('default is no Spring in application') — offer PRD update at Finalize. Prevents: a shared composition-root @Configuration that every new resource must edit, which would break FR-6/SM-2.
- (decision) Domain model and JPA entity are SEPARATE types with an explicit mapper. Pure immutable Kotlin domain class with value-class ids in domain/<resource>; @Entity class in adapter/out/persistence/<resource>; mapping is explicit code, no mapping framework (MapStruct etc. rejected — SM-C2 dependency footprint). Prevents: Hibernate's mutable-var / no-arg-ctor / lazy-proxy semantics leaking into the domain and quietly eroding the Boundary Rule. Cost accepted: ~3 files + a mapping function per resource, in every Consumer Service.
- (direction) STANDING PRINCIPLE from user: 'keep scaffolding as simple as possible'. Governs every remaining call in this run — prefer the option with the least owned code, fewest concepts and fewest files, and only pay complexity where leaving it out would guarantee divergence between Consumer Services. Reconciles with SM-C2 (lean dependency footprint) and SM-C3 (single-digit parameter files). Where a simpler option was rejected, the memlog says why.
- (decision) Cache-aside is orchestrated by the APPLICATION use case, not a decorator and not Spring @Cacheable. The use case holds two outbound ports (repository + cache) and does read-through / invalidate-on-write itself. Prevents: three plausible cache homes across resources. Rationale: staleness tolerance is a policy call; the pattern stays visible in the code an agent copies; FR-12's 'a hit avoids the datastore' is directly assertable with two fakes and no proxy semantics.
- (decision) Identifiers = application-generated UUID v4 via UUID.randomUUID(), wrapped in a per-resource @JvmInline value class (e.g. WidgetId). Postgres column type uuid. Prevents: mixed id strategies and nullable-until-flush ids. Chose v4 over v7 under the simplicity principle — v7 needs a hand-rolled ~20-line generator; if btree insert locality ever matters it is a one-line swap inside <Id>.new(). Rejected DB bigserial: id absent until flush forces a nullable id through the immutable domain model.
- (decision) REST URL convention = /api/v1/{resource}, plural lowercase resource names. Standard CRUD verb map: POST collection = create (201 + Location), GET /{id}, GET collection = paged list, PUT /{id} = full update, DELETE /{id} = 204. Prevents: per-resource path and versioning improvisation. The /api prefix also gives the Auth Seam and any ingress a single matcher that is cleanly disjoint from /actuator.
- (decision) Pagination = offset style, ?page= (0-based) and ?size= (documented default), response envelope {items,page,size,totalElements,totalPages}. The Starter defines its own PageRequest/PageResult value types in the shared package because the Boundary Test bans org.springframework.data from the application layer; the persistence adapter translates to and from Spring Data's Pageable/Page. Prevents: each resource inventing a list contract. Rejected cursor paging (needs a per-resource stable sort key, less familiar to extend) and no-pagination (guarantees divergence).

- (decision) JVM = Java 25 (current LTS), set via a Gradle toolchain so the build is independent of the developer's local JDK. Rationale: Boot 4 has first-class Java 25 support and Java 21's permissive-license updates lapse this month.
- (decision) Structured JSON logging uses Spring Boot's BUILT-IN structured logging (logging.structured.format.console), not logstash-logback-encoder and not a hand-written logback XML. Satisfies FR-22 with zero dependencies and no owned config file. Simplicity principle applied.
- (decision) Liveness/readiness probes are enabled by default in Spring Boot 4, so FR-19/SM-5 need no probe wiring — only the readiness health-group membership is stated explicitly.
- (decision) bootBuildImage: builder pinned to an explicit paketobuildpacks/builder-noble-java-tiny tag (never a floating tag — reproducibility NFR). BP_JVM_CDS_ENABLED and AOT cache stay OFF in v1: there is an open Paketo issue (paketo-buildpacks/spring-boot#581) where CDS on Java 25 + Boot 4 fails the build with 'unable to contribute spring-performance layer'. Revisit when that issue closes.
- (decision) OQ-6 SETTLED: Boundary Test tool = ArchUnit 1.5.0, not Konsist. Rationale: ArchUnit's layeredArchitecture() DSL maps 1:1 onto the chosen layer-first package roots, so the whole rule set is a dozen readable lines; mature, JVM-standard, Java 25 class-file support current. Konsist rejected: younger, smaller community, and its value (Kotlin-native DSL) does not pay for itself against layeredArchitecture().
- (decision) Version catalog scope: gradle/libs.versions.toml pins ONLY what the Spring Boot BOM does not manage — Kotlin, the Boot and Kotlin Gradle plugins, springdoc, ArchUnit, Spotless/ktlint. Flyway, Testcontainers, the Postgres driver, Micrometer, Lettuce and Logback come from the Boot BOM with no version literal. Satisfies FR-1 (no version literals in build files) while keeping the catalog small and upgrade-by-Boot-bump mechanical.
- (decision) OQ-7 SETTLED: no separate integrationTest Gradle source set. One test source set; Integration Tests carry JUnit @Tag("integration"); a single abstract base class (e.g. IntegrationTestBase) owns static Testcontainers Postgres + Redis annotated @ServiceConnection, started once per JVM and shared. A new resource's Integration Test extends the base and adds nothing infrastructural — this is the concrete mechanism behind FR-6 and SM-2. Flyway migrates the container on context start; test isolation is by per-test data cleanup, not per-test containers.
- (decision) OQ-3 SETTLED: springdoc-openapi 3.1.1 (springdoc-openapi-starter-webmvc-ui). OpenAPI JSON served in every profile; Swagger UI enabled only under the 'local' profile via springdoc.swagger-ui.enabled. Prevents an interactive UI being exposed in production without anyone deciding to.
- (decision) OQ-4 SETTLED: no OpenTelemetry collector in the Compose Stack in v1. Compose = Postgres + Redis only. Tracing stays configuration-only (OTLP endpoint unset locally = exporter no-op). Simplicity principle; overturns the PRD FR-25 assumption — offer PRD update at Finalize. Deferred: add a collector + Jaeger/Tempo profile when someone actually needs to read a local trace.
- (decision) OQ-5 SETTLED: actuator exposure = health, info, prometheus only (management.endpoints.web.exposure.include). Under the Auth Seam: /actuator/health and its liveness/readiness groups stay unauthenticated (probes must not need credentials); every other actuator endpoint requires a valid token. Actuator stays on the main port in v1 — a separate management port is deferred.
- (decision) Error model concretes: Problem Detail 'type' = about:blank in v1 (no per-code doc URIs to host and keep alive); 'instance' = the request path (Spring default); extension members are 'code' (string, the Error Code), 'traceId' (correlates the response with the JSON log line per FR-40), and 'errors' for validation failures — an array of {field, code, message}. One shape for all 4xx/5xx, no second schema.
- (decision) Error Code catalogue = a single Kotlin enum ErrorCode in domain/shared/error. Each constant carries a status-free ErrorKind (VALIDATION, NOT_FOUND, CONFLICT, INTERNAL) plus a default message template. BusinessException/SystemException carry an ErrorCode + a params map; neither carries an HTTP status. The ErrorCode -> HTTP status map lives ONLY in the GlobalExceptionHandler (adapter/in/web/shared), because the Boundary Test forbids HTTP types in domain. Known tension accepted: every new resource appends to this shared enum — that is domain code, not Plumbing (FR-6 unaffected), and FR-39 explicitly requires one enumerable catalogue.
- (decision) Transaction and cache ordering rule: @Transactional appears ONLY on application-layer use cases — never on controllers, never on adapters; read paths use readOnly=true. The cache may be EVICTED inside a transaction (a rollback then leaves the cache merely cold, which is safe) but must NEVER be POPULATED inside a write transaction. Prevents: uncommitted or rolled-back state being served from Redis, and per-resource disagreement about where the transaction starts.
- (decision) Postgres and Redis image tags live in a single root .env file: Docker Compose reads it natively, and the Gradle build reads it to pass the tags to Testcontainers as system properties (~4 lines). Prevents CI and local development silently running different Postgres majors — the failure mode FR-25's 'versions matching what CI uses' is guarding against.
- (decision) CI builds the image on push to main only, never on pull requests. PR pipeline = format check + Boundary Test + Unit + Integration Tests. Protects SM-C1 (~10 min pipeline).
- (decision) Web/DTO conventions: adapter/in/web/<resource> holds <Resource>Request / <Resource>Response DTOs; the domain type is never serialized directly and never appears in a controller signature. Flyway migrations are db/migration/V<n>__snake_case.sql, sequential integers, never edited after merge (checksum validation on, no auto-repair). Config = application.yaml with env-var placeholders + application-local.yaml holding the only literal local credentials.
- (decision) OQ-1 SETTLED: Registry = ghcr.io, PRIVATE package. CI pushes with the workflow's built-in GITHUB_TOKEN under a 'permissions: packages: write' block — no stored secret to rotate. The cluster pulls via a single imagePullSecret built from a PAT with read:packages, owned and referenced by the separate charts repo. Resolves the PRD Glossary 'Registry' definition and FR-30's credential detail.
- (decision) OQ-2 SETTLED: Redis is a HARD dependency — fail fast, no degraded mode. OVERTURNS the PRD FR-10 assumption (degrade-to-Postgres-with-warning); offer PRD update at Finalize. Mechanism: Spring Data Redis connects lazily, so 'fail fast' is implemented as the Redis health contributor being a member of the readiness health group — the pod never reports ready without Redis, and Kubernetes never routes to it. The cache adapter carries NO try/catch and NO fallback path; a Redis failure surfaces as a SystemException -> 500. Chosen because it is by far the least code and the least hidden behavior; the cost accepted is that a Redis outage takes the service out of rotation even though Postgres could still serve every request.
- (decision) Base package is FIXED across every Consumer Service: com.hl.service (confirm the exact string in review). It is NOT one of the Four Parameters and is never renamed. Prevents: a package-rename step that is real source-code editing, would appear in every ArchUnit rule literal, and would be the most error-prone item in the README checklist — exactly the work the deferred generator (FR-35) was meant to absorb. Makes FR-34's 'no source code change required' literally true and protects SM-1 (<15 min clone-to-green). Cost accepted: two Consumer Services share a package namespace, which is harmless since they are separate deployables.
- (decision) Auth Seam mechanism: a single SecurityFilterChain bean pair gated by the property app.auth.enabled (default false). Disabled mode installs an EXPLICIT permitAll chain — required because spring-security on the classpath would otherwise secure everything with a generated password, which is the opposite of the documented v1 posture. Enabled mode requires JWT on /api/**, leaves /actuator/health** open, and requires a token for every other actuator endpoint. Fail-safe is inherent: with app.auth.enabled=true and no spring.security.oauth2.resourceserver.jwt.issuer-uri, the JwtDecoder cannot be built and the context fails to start — it can never silently allow-all.
- (decision) Runtime envelope: server.shutdown=graceful with spring.lifecycle.timeout-per-shutdown-phase=30s (documented default, env-overridable) satisfying FR-23/FR-32. No explicit -Xmx: the buildpack's container-aware JVM memory calculator owns heap sizing; the README documents the knob (JAVA_TOOL_OPTIONS / BPL_JVM_*) rather than the Starter fixing a number. Readiness health group = db + redis. Startup-to-readiness target <10s (PRD NFR) measured on the documented local check (FR-32).
- (decision) Tracing: Micrometer Tracing with the OTel bridge and an OTLP exporter. management.tracing.sampling.probability defaults to 1.0 with a documented env override; because the OTLP endpoint is unset by default the exporter is a no-op locally and in CI, satisfying FR-21 with no profile-specific code path. Trace and span ids reach the JSON logs via the built-in structured logging MDC, and the same trace id is echoed as the Problem Detail 'traceId' extension member.
- (decision) Test conventions: JUnit 5 + AssertJ (both already in the Boot test starters — no new dependency). NO mocking framework in v1: outbound ports are small interfaces, so Unit Tests use hand-written in-memory fakes. Rationale: SM-C2 dependency footprint and the simplicity principle; a fake is more legible to an agent than a mock DSL. FLAG FOR REVIEW — this is the most opinionated call of the run and Alex may reasonably want MockK instead.

Plus explicit noClasses().that().resideIn(..) bans: domain -> no org.springframework.., no jakarta.., no org.hibernate..; application -> no org.springframework.web.., no org.springframework.data.., no org.springframework.http.., no jakarta.persistence.., no jakarta.servlet.., no org.hibernate.. (only org.springframework.stereotype and org.springframework.transaction.annotation permitted).
