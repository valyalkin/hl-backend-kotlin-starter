- (decision) Create intent confirmed: brief for an internal Spring Boot + Kotlin starter service used as the baseline template for all future Kotlin backend services in the stack.
- (decision) Working mode: Coaching path (section-by-section, with pushback). Form factor understood as an internal developer scaffold; users are backend engineers cloning/forking it for new services.
- (change) Scope facts: greenfield (no existing services); user has built this manually before; must be CI/CD- and Kubernetes-ready — proper health endpoints (liveness/readiness), deploys to user's own server.
- (decision) Core value prop: stand up a new production-ready service in minutes by changing a small set of parameters; each new service serves a different purpose (domain logic swapped, infra plumbing reused). Solo user for now; not open-source; fork-and-adapt model.
- (change) Parameters to change per new service: service name, database name + creds, HTTP port, image name. Deployment: Helm chart + Argo CD (GitOps). Open: rename mechanism vs manual checklist; whether an example vertical slice ships; whether the Helm chart lives in the starter repo.

(c) Helm chart lives in a SEPARATE charts repo — out of scope; starter delivers a well-behaved container image + CI that builds/tests/pushes it.
- (change) Added consumer: AI coding agents will use the starter to scaffold new services and add functionality — so predictable structure, consistent conventions, and strong tests as guardrails matter for agent-legibility, not just human DX.
