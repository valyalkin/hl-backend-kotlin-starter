Post-run: all four medium findings and the quick lows below were fixed in prd.md right after this run, and the PRD was finalized (status: final). This report is the snapshot that drove those fixes; the change list is in the run memlog.

A disciplined, well-shaped capability spec for an internal build substrate. The thesis — plumbing that AI agents will extend, so structure must be enforced not merely documented — is stated, and the features follow from it. Scope honesty is high and, after the architecture reconciliation, the open-items surface is small: six still-open assumptions, one NOTE FOR PM, zero open questions.

What keeps it from a clean bill are four medium gaps the reconciliation introduced or exposed: the readiness-probe requirement (FR-19) was not updated alongside the rest of the Redis hard-dependency decision; the accepted availability cost of that decision is unstated; the pagination contract has no FR home (it lives only in the architecture); and the Auth Seam’s treatment of the /v3/api-docs endpoint is unspecified. None block the architecture (already complete) and all are small edits — but they should be closed before epics and stories source-extract from this document.

medium

Redis hard-dependency trade-off is unstated

§4.4 FR-10, §11
The mechanism is specified (readiness gates on Redis, no fallback) but the accepted cost is not — the service’s availability is now bounded by Redis’s, for a component introduced as a read optimisation, when Postgres alone could still serve every request. The architecture memlog accepted this explicitly.
Fix: add one sentence to FR-10 or §11 Constraints naming the availability coupling as an accepted cost.

Adversarial review

review-adversarial-general.md

Stance: assume the reconciliation introduced seams — places where a decision folded in from the architecture now contradicts an older paragraph, or where “resolved” hides an unanswered question.

medium

The readiness probe spec was not updated with the rest of the Redis decision

§4.7 FR-19
FR-10, the §4.4 description, §6.1 and §9.2 all say readiness gates on Redis. FR-19 — the actual readiness requirement — still says readiness “reflects readiness to serve, including datasource availability” and stops there. An engineer implementing FR-19 from the PRD wires only the datasource, dropping the load-bearing half of “fail fast, no degraded mode”.
Fix: FR-19 consequence → “…including datasource and Redis availability (FR-10).”
medium

/v3/api-docs in production, auth status unspecified

§4.6 FR-18, §4.12 FR-37
FR-18 commits to serving the OpenAPI JSON “in every profile” including production. FR-37 defines the Auth Seam’s endpoint posture only for actuator paths; /v3/api-docs is neither actuator nor under /api/v1/**. When the seam is enabled the PRD does not say whether the API schema is served to anonymous callers in production — a security-relevant decision with no home.
Fix: add a line to FR-18 or FR-37 (“requires a token when the Auth Seam is enabled” or “stays open; schema not considered sensitive”) and reflect it in the FR-38 README section.
medium

Pagination has a description but no requirement

§4.5 FR-13
“Lists paged” with no parameters or body shape. AD-10 defines ?page=/?size= and the five-field envelope, but epics/stories source-extract from the PRD, not the architecture.
Fix: fold the offset-paging parameters and envelope shape into FR-13 as a testable consequence, or add FR-13a.
low

“Redis a hard dependency” vs UJ-1’s parity promise

§2.3 UJ-1
With Redis able to hold the pod out of rotation, “Redis didn’t start locally” now looks identical to a production outage — arguably good (parity), but the PRD never connects the two.
Fix: a sentence in UJ-1’s edge-case list (“Redis not up → readiness never goes green, same as prod”).
low

.env is new Plumbing the Four-Parameters story doesn’t mention

§4.8 FR-25, §4.11 FR-33
FR-25 introduces a root .env holding Postgres/Redis image tags. SM-C3 counts “one home per parameter”; a reader could wonder whether the HTTP port or DB name also lives there. They do not.
Fix: FR-25 or FR-33 — “the .env file holds only Postgres/Redis image tags and is not one of the Four Parameters’ homes.”
low

“Resolved in architecture” is doing two different jobs

throughout §4
Some tags mark a genuine reversal of a stated PRD position (FR-5, FR-10, FR-25); others just record that an open assumption got a concrete value (FR-1, FR-3, FR-8, FR-13, FR-22). A reader skimming for “what changed” can’t tell them apart.
Fix: consider “Overturned by AD-x” vs “Settled by AD-x”.
